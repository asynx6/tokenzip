# Contributing

Zero dependencies is the product. PRs that add an npm install will be
closed with a link to this file, no hard feelings.

## Layout

```
tokenzip.js      CLI arg parsing + output (no logic here — keep it in lib/)
lib/tokens.js    provider formulas (see FORMULAS.md for provenance rules)
lib/optimize.js  effective-size + budget-search math (pure, easy to test)
lib/png.js       PNG read/write/resize (8-bit, non-interlaced)
lib/jpeg.js      baseline JPEG read/write (4:4:4 + 4:2:0; see below)
test-*.js        node <file>, zero deps, exit 1 on failure
bench.mjs        regenerates the README benchmark table
gen-demo.mjs     regenerates the README chart (drawn with our own encoder)
```

## The JPEG codec in 60 seconds

`lib/jpeg.js` is a full baseline-JPEG pipeline written to ITU-T T.81:

- **Encode**: RGB→YCbCr, 2×2 box-average chroma subsample (4:2:0), level
  shift −128, forward DCT (two-pass 8×8 matrix multiply with precomputed
  cosine table `COS`), quantize with scaled Annex-K tables (`scaleTable`,
  quality knob), zigzag scan via `ZIG` (generated against the canonical
  diagonal walk — see comment), Huffman-encode DC (differential) + AC
  (run-length) with standard tables, byte-stuff 0xFF markers.
- **Decode**: marker walk (SOI/APP0/DQT/SOF/DHT/SOS), Huffman decode +
  dequant + inverse DCT per 8×8 block, nearest upscale chroma to full-res
  planes, YCbCr→RGB. Progressive and lossless modes throw with a clear
  message on purpose — that's the honest v0.x gap.

Two tables have bitten every implementer; here's how this repo keeps them
honest:

1. `HT` (Huffman code lengths + symbol orders) — transcribed byte-exact
   from libjpeg-turbo `jcmaster.c` `std_huff_dht[]`, NOT from memory.
2. `ZIG` — generated by the (row,col) diagonal walk and cross-checked; a
   one-index swap silently corrupts all AC energy (learned the hard way in
   v0.2 development, see `test-jpeg.js` "solid/vgrad/hgrad" ladders).

## How to add a codec (e.g. WebP) or provider

- One file in `lib/`, exported pure functions, no side effects.
- Format support in the CLI = teach `imageOf()` + the `--out` branch in
  `tokenzip.js`.
- Tests in `test-<format>.js`: roundtrip (encode→decode→pixel-assert) is
  the minimum; cross-validation against an independent decoder is strongly
  preferred (see `verify-jpeg.ps1` using Windows GDI+).
- New providers go in `lib/tokens.js` + `PROVIDERS` + `FORMULAS.md` entry
  with source URL and verification date.

## Run everything

```bash
node test-tokens.js && node test-png.js && node test-jpeg.js
node bench.mjs          # updates README numbers — paste real output
node gen-demo.mjs       # regenerates demo.png
```

Windows-only extras: `powershell -File verify-jpeg.ps1` runs the GDI+
cross-validation; CI on Linux exercises the same code paths through our own
encoder/decoder pair.

## Style

ESM, no TypeScript, no build step, comments explain WHY not WHAT, keep the
diff small, and if a test starts redlining your change, the test is right.
